## 1. Цель

Перевести прошивку с прямого управления клапанами и кнопками через GPIO ESP32 на **I²C-расширитель PCAL9555APW**, добавить **диагностику клапанов по ST-выводам PROFET**, **импульсный вход скорости** и **дискретный датчик аварийно низкого давления**, сохранив без регресса всю текущую функциональность (ручной/авто/движение, калибровка, OTA, UI, меню).

Критерий успеха: на новой плате (плата v2) прошивка 11.0.0 выполняет все функции 10.15.6 + новые, проходит стендовые тесты из §9, безопасно ведёт себя при сбоях I²C/расширителя (fail-safe: клапаны закрыты).

## 2. Новая аппаратная карта (обязательная)

### 2.1 ESP32 (U9)

| GPIO | Назначение | Режим |
|---|---|---|
| 21 / 22 | I²C SDA / SCL (JHM1200, MPU6050, **PCAL9555APW**, J4/J6) | I²C 400 кГц |
| 32 | **VLV_EN** — разрешение буфера U5 74HCT541 (OE) | выход; **LOW = буфер включён, HIGH/Hi-Z = клапаны закрыты (fail-safe)** |
| 33 | **INT_MCU** — прерывание PCAL9555APW (open-drain, активный низкий) | вход, прерывание по фронту |
| 35 | **SPEED_PULSE** — импульсы датчика скорости | вход (input-only), PCNT |
| 25 | **PRES_SW** — аварийный датчик давления в рессивере | вход с подтяжкой, активный низкий |
| 23/18/5/16/19/4 | TFT ST7789 (MOSI/SCLK/CS/DC/RST/BL) | без изменений |
| 13/12/15/17/34 | **бывшие кнопки — больше не используются** (на плате NC) | не инициализировать как GPIO |
| 32/33/25/26/27/14 | **бывшие клапаны — на плате NC** | не инициализировать |

### 2.2 PCAL9555APW (U6) — 16 бит

Адрес I²C: **0x20** (A0…A2 = GND), питание +3V3, INT open-drain, внешние подтяжки стоят на плате.

| Бит | Пин U6 | Цепь | Назначение |
|---|---|---|---|
| P00…P03 | 4…7 | `VLV_IN1…4` → U5 → BTS724G | клапаны подушек: ПЛ, ПП, ЗЛ, ЗП |
| P04 | 8 | `VLV_IN5` | INFL (общий впуск) |
| P05 | 9 | `VLV_IN6` | DEFL (общий выпуск) |
| P06, P07 | 10, 11 | `ST_U3_12`, `ST_U3_34` | флаги неисправностей U3 (BUB1+BUB2 / BUB3+BUB4) |
| P10, P11 | 13, 14 | `ST_U4_12`, `ST_U4_34` | флаги U4 (INFL+DEFL / неиспользуемые каналы) |
| P12…P16 | 15…19 | `BUT1…BUT5` | кнопки KN1…KN5 (активный низкий) |
| P17 | 20 | — | резерв (не использовать без согласования) |

**Логика ST:** open-drain, активный низкий: `0` = неисправность пары каналов (обрыв/КЗ/перегрев по даташиту BTS724G). Внешние подтяжки 10 к к +3V3.

**Буфер U5:** входы — PCAL (3,3 В push-pull), выходы — 5 В на входы BTS724G. `VLV_EN` = OE1/OE2 (пины 1 и 19) через инвертор/подтяжку: **HIGH = Hi-Z = все клапаны закрыты**.

### 2.3 Новые входы (J7, J8)

| Разъём | Цепь | Схема согласования | Требование к ПО |
|---|---|---|---|
| **J7** (1×4, датчик скорости КАМАЗ 4222.3843/ПД8089, 8 имп/об) | `SPEED_PULSE` | 8 В → делитель → Шмитт 74LVC1G14 → IO35 | PCNT, V = F·3600/K |
| **J8** (1×2, 6032.3829, 5±0,5 кгс/см²) | `PRES_SW` | 100 к↑/10 к/клэмп 3,3 В → IO25 | активный низкий, антидребезг 50 мс |

Питание датчика скорости: 8 В от U11 78L08 (или от штатного спидометра через JP1) — **ПО это не касается**, но датчик может отсутствовать: все новые входы должны иметь конфиг «включено/выключено».

## 3. Архитектурные требования

### 3.1 Новый слой: `pcal9555.h/.cpp`

Обязательный API (имена можно скорректировать, семантику — нет):

```cpp
class Pcal9555 {
public:
  bool begin();                              // Wire уже поднят; проверка наличия (read 0x00/0x01)
  bool isPresent();
  bool writeOutputs(uint16_t value);         // регистры 0x02/0x03, read-back проверка
  bool readInputs(uint16_t &value);          // регистры 0x00/0x01
  bool setOutputBits(uint16_t mask);         // read-modify-write под xI2CMutex
  bool clearOutputBits(uint16_t mask);
  bool setDirection(uint16_t mask);          // 0x06/0x07: 1=вход
  uint16_t lastOutputs() const;
  uint16_t lastInputs() const;
  uint32_t errorCount() const;
  bool configureAgileOutputs();              // drive strength max для выходных битов
};
extern Pcal9555 g_pcal;
```

Требования:
- регистры: `0x00/0x01` input, `0x02/0x03` output, `0x04/0x05` polarity (0x0000), `0x06/0x07` config (**P00…P05 — выходы, остальные — входы**), Agile I/O — установить максимальную силу выходов для P00…P05 (сверить с даташитом PCAL9555A); INT — маска по необходимости (ST и кнопки).
- все обращения — под `xI2CMutex` (уже есть), таймаут/повторы: 3 попытки по 2 мс, затем ошибка.
- кэш `lastInputs`/`lastOutputs` обновлять после каждой успешной транзакции; **read-back** после записи выходов; при расхождении — повтор и, если не помогло, `ErrorHandler::VALVE`.
- при старте: `VLV_EN = HIGH` (буфер Hi-Z) **до** первой инициализации PCAL; инициализация: config → outputs = 0x0000 → проверка read-back → `VLV_EN = LOW` только после успеха.
- если `begin()` не удался: остаться в safe state (`VLV_EN=HIGH`), поднять `ERR_VALVE` с сообщением «НЕТ СВЯЗИ С РАСШИРИТЕЛЕМ», повторять инициализацию с backoff (1 с), UI — ошибка.
- **INT**: `attachInterrupt(digitalPinToInterrupt(33), ..., FALLING)`; ISR только `portDISABLE_INTERRUPT`-безопасный флаг/`xTaskNotifyFromISR`; обработка — в задаче; INT снимается чтением input-регистров.

### 3.2 Клапаны (`valve_ctrl.cpp`, `task_valve.cpp`)

- `bubPins[]` больше не GPIO: заменить на битовую карту `VLV_BIT[PAD_COUNT] = {0,1,2,3}`; INFL → P04, DEFL → P05.
- `setValve(pad,state)`, `closeAllValves()`, `emergencyStop()`, `forceAllValvePinsLow()` — переписать через `g_pcal.setOutputBits()/clearOutputBits()`; публичный API `valve_ctrl.h` **не менять**.
- `emergencyStop()`: **сначала** `VLV_EN = HIGH` (аппаратное отключение буфера, ≤ 1 мс), **затем** outputs = 0; защёлка сохраняется как сейчас (`s_emergencyLatched`).
- `task_valve.cpp`: заменить все `digitalWrite(PIN_INFL/PIN_DEFL/bubPins[i], ...)` на битовые операции; сохранить тайминги/таймауты (`VALVE_OPERATION_TIMEOUT_MS`, `VALVE_MAX_COMMAND_MS`), синхронные ack, OTA-лок, `manifoldBusy`.
- после каждой команды — read-back выходов; при ошибке I²C: 3 попытки → `ERR_VALVE` → emergencyStop.
- при `xValveMutex`-таймауте, как и сейчас, разрешён «жёсткий» путь через VLV_EN (без I²C).

### 3.3 Кнопки (`btn_io.cpp`, `task_button.cpp`, `.ino`)

- `btnDigitalRead(pin)`: PIN_BUT1…PIN_BUT5 (13/12/15/17/34) остаются **виртуальными идентификаторами**; фактическое значение — из кэша `g_pcal.lastInputs()` (биты P12…P16), инверсия: нажата = `0`.
- `Button button0..button3` создаются как сейчас; **добавить `button4(PIN_BUT5, INPUT_PULLUP, LOW)`** и KN5.
- обновление кэша PCAL: в `buttonTask` каждый цикл (20 мс) или по INT (быстрее); после `readInputs` сбрасывать флаг INT.
- EncButton (debounce/hold/step/combo) не менять; combo (КН1+КН2, КН3+КН4, авария КН1+КН4) должны работать через виртуальные пины.
- **KN5 (новая кнопка):** длинное нажатие ≥ 2 с — сброс аварийной защёлки (`resetEmergencyLatch()`) при её активности; короткое — игнор (не конфликтовать с меню). Если HW-кнопка отсутствует — конфиг `btn5Enabled=false`.
- при ошибке чтения PCAL: кнопки считаются отпущенными (fail-safe), событие ошибки не спамить (rate-limit 1/с).

### 3.4 Диагностика ST (новый модуль `valve_diag.h/.cpp`)

- карта: `ST_U3_12` → пад 0,1; `ST_U3_34` → пад 2,3; `ST_U4_12` → INFL/DEFL; `ST_U4_34` → игнорировать (неиспользуемые каналы), но читать и логировать при изменении.
- при `ST=0` (fault): (1) закрыть соответствующую пару/канал, (2) `ErrorHandler::VALVE` с текстом «НЕИСПРАВНОСТЬ КЛАПАНА: <группа>», (3) **не открывать** канал(ы) до сброса оператором, (4) запись в лог/событие.
- идентификация виновника внутри пары: поочерёдное включение каналов пары на 30 мс с контролем ST; при повторном fault — блокировка конкретного канала; ограничить частоту попыток (не чаще 1/5 с), не выполнять при движении.
- если ST активен при всех закрытых клапанах — трактовать как обрыв/КЗ, пару не открывать.
- новый `EventType::VALVE_FAULT` (data: маска каналов/группа) и строка для UI.
- опрос ST: 20–50 мс в `buttonTask`/`controlTask` (по INT — приоритетно).

### 3.5 Импульсный вход скорости (`speed_input.h/.cpp`)

- инициализация PCNT (unit 0, канал 0, GPIO35, фильтр glitch ≈ 1 мкс, счёт по фронту); счётчик 16-бит — программное расширение переполнения.
- окно измерения: 500 мс (в `controlTask`), `F = Δcount / Δt`; фильтр: медиана 3 + EMA (α ≈ 0.3); при отсутствии импульсов > 1 с → `V = 0`, `valid=false`.
- `V[км/ч] = F · 3600 / K`, `K` (имп/км) из конфига, диапазон 1001…25000, дефолт 8000; калибровка: ручной ввод K или измерение по известному пути (сервисный экран).
- плаусибельность: 0…200 км/ч; вне диапазона — ошибка `ERR_SPEED` (новый код) + `valid=false`; при `speedSensorEnabled=false` — всегда 0 без ошибок.
- одометр: интеграл `V·dt` (м), сохранять в LittleFS раз в 60 с (или в конфиг/отдельный файл) — для логов.
- использование:
  - **MOVEMENT-режим**: детектор движения = `V ≥ movementSpeedKph` (дефолт 3 км/ч) непрерывно `movementDurationSec`; выход — `V < порога` `movementSettleSec`; IMU-детектор оставить как резерв (флаг `movementUseImu`).
  - **безопасность**: при `V > maxSpeedForLeveling` (дефолт 3 км/ч) запрещать AUTO-регулировку и ручные импульсы накачки (DEFL разрешён); UI — индикация «ДВИЖЕНИЕ».
  - отображение скорости в основном экране (км/ч), одометр — в «Информации».

### 3.6 Аварийное давление (`pressure_switch.h/.cpp`)

- GPIO25: `INPUT_PULLUP`; активный низкий (`0` = давление ниже порога) — полярность конфигом `presSwActiveLow` (дефолт `true`); антидребезг 50 мс (счётчик подряд идущих значений), опрос в `buttonTask` (20 мс) или по прерыванию.
- при срабатывании: `ErrorHandler::LOW_PRESSURE` с текстом «АВАРИЙНО НИЗКОЕ ДАВЛЕНИЕ В РЕССИВЕРЕ»; блокировать INFL и клапаны подушек; DEFL разрешить; UI — значок/сообщение.
- при снятии: `markErrorCleared` (существующая задержка 3 с); повторное срабатывание — снова ошибка.
- сверка с JHM1200: если JHM1200 показывает давление магистрали > `presLowBar` (дефолт 4,9 бар), а switch активен > 2 с — `ERR_SENSOR` (несоответствие датчиков) + блокировка накачки; лог.
- при `presSwEnabled=false` — вход игнорируется, ошибок нет.
- не дублировать существующую логику `masterLowBar` (оставить как есть); новый датчик — независимый аппаратный контроль.

### 3.7 IMU / гироскоп J6

- изменений нет: та же I²C-шина (`xI2CMutex`), адрес MPU6050 0x68, JHM1200 — свой; новый внешний гироскоп в J6 использует те же линии — ПО не требует изменений, кроме устойчивости к «занятой» шине (таймауты I²C).

### 3.8 Safe state, watchdog, восстановление

- boot order (в `setup()`): `pinMode(VLV_EN)`, `digitalWrite(VLV_EN, HIGH)` → очереди/мьютексы → `Wire.begin` → PCAL init → `VLV_EN=LOW` → остальное (TFT, LittleFS, DMP, задачи).
- `emergencyStop()` (аварийная защёлка, WDT, VALVE-ошибка): `VLV_EN=HIGH` + outputs=0 + защёлка.
- при ошибке I²C (PCAL NAK/read-back mismatch) ≥ 3 подряд: `VLV_EN=HIGH`, `ERR_VALVE`, попытка переинициализации раз в 1 с; при успехе — outputs=0, `VLV_EN=LOW` только по явному разрешению (не автоматически, если была активная операция).
- WDT: новые модули не должны блокировать задачи; `esp_task_wdt_reset()` — только в существующих задачах; INT-обработчик — без I²C.
- при brownout/reset: клапаны закрыты аппаратно (VLV_EN pull-up) — ПО обязано после старта не открывать клапаны до завершения инициализации.

### 3.11 Тестовая обвязка (`test_harness.cpp`, `service_ui.cpp`)

Serial-команды (обязательные, для стенда и автотестов):
- `SIM SPEED <км/ч>` — подмена значения скорости (не PCNT) для проверки MOVEMENT/UI;

## 5. Fail-safe требования (обязательные)

1. При reset/зависании MCU, до инициализации PCAL: `VLV_EN=HIGH` (подтяжка на плате) → буфер Hi-Z → BTS закрыты → **все клапаны обесточены**.
2. При сбое I²C/NAK PCAL: outputs=0 `VLV_EN=HIGH` в течение ≤ 100 мс; ошибка `VALVE`.
3. При ST-fault: запрет открытия соответствующей группы до сброса оператором.
4. При аварийном низком давлении: запрет INFL и клапанов подушек; DEFL разрешён.
5. При движении (`V > maxSpeedForLeveling`): запрет AUTO-регулировки и накачки; только DEFL.
6. Emergency latch (существующий) сохраняется; сброс — только оператором (UI или KN5 long-press).
7. Все клапаны закрываются при: OTA-сессии (как сейчас), WDT-сбросе, ошибке `VALVE`, ошибке `LOW_PRESSURE`.

## 8. Риски и допущения

- PCAL9555APW питается 3,3 В; входы U5 (HCT) с порогом 2,0 В — уровни проверены; при замене платы на TCA9535PWR (pin-to-pin fallback) ПО не меняется, но у TCA нет Agile I/O — `configureAgileOutputs()` должен корректно отрабатывать отсутствие регистров (игнорировать NAK на 0x40…0x4F).
- ST-флаг общий на пару каналов — точная идентификация канала возможна только поочерёдным включением (E2), не гарантируется при КЗ.
- Датчик скорости: 4222.3843/ПД8089 — активный импульсный (8 В), 8 имп/об; если на машине стоит индуктивный 2-проводный — HW не поддерживает без доработки (вне объёма).
- Переключатель 6032.3829: 5 ± 0,5 кгс/см² (≈4,9 бар); полярность/нормально-замкнутость зависит от исполнения — конфиг.
- Кнопка KN5 физически есть в J3 (BUT5); если в конкретной сборке её нет — `btn5Enabled=false`.
- 8 кГц PCNT при 200 км/ч и 8 имп/об ≈ 444 Гц — запас большой; для 1 имп/об — до 55 Гц, тоже ок.
- ESP32 без PSRAM: стек новых модулей минимален; INT-обработчик без I²C.

## 9. Критерии приёмки

### 9.1 Сборка и статика
- сборка Arduino/PlatformIO (esp32, текущая конфигурация платы) **без ошибок и предупреждений** уровня `-Wall` (или зафиксировать baseline);
- размер прошивки ≤ 10.15.6 + 5 % (baseline: flash **1 607 230 Б**, RAM globals **86 680 Б**, свободно 241 000 Б); свободной RAM ≥ 20 КБ в покое;
- `MODULES.md`/`RELEASE_NOTES.md` обновлены; версия `11.0.0`.

### 9.2 Стенд (обязательные проверки)
1. **VLV_EN**: при включении/сбросе до инициализации — HIGH (клапаны закрыты); после init — LOW; при `emergencyStop` — HIGH ≤ 1 мс.
2. **Клапаны**: поочерёдно открыть/закрыть все 6 (ПЛ/ПП/ЗЛ/ЗП/INFL/DEFL), проверить индикаторы D11–D16 (LED под своим пином J2) и read-back PCAL.
3. **Кнопки**: KN1…KN5 читаются; combo КН1+КН2 (АВТО/РУЧ), КН3+КН4 (меню), КН1+КН4 (авария); KN5 long ≥ 2 с снимает аварийную защёлку.
4. **ST-диагностика**: отключить катушку (обрыв) → ST-флаг ≤ 100 мс → `ОШИБКА КЛАПАНА`, канал блокирован; КЗ на GND → то же; после устранения — сброс оператором.
5. **Скорость**: генератор 1 кГц (или N имп/с) → `V = F·3600/K` с точностью ±5 %; при пропадании импульсов > 1 с → 0; `SIM SPEED` меняет UI/логику; MOVEMENT входит/выходит по порогам.
6. **Давление**: замыкание J8 на GND → `НИЗКОЕ ДАВЛЕНИЕ` ≤ 100 мс, накачка заблокирована, DEFL работает; размыкание → сброс через 3 с.
7. **Сбой I²C**: отключить SDA/питание PCAL → `ERR_VALVE` + `VLV_EN=HIGH` ≤ 100 мс; восстановление — реинициализация.
8. **Регресс**: MANUAL/AUTO/CALIB/MOVEMENT/OTA/Wi-Fi/меню/калибровка JHM — без изменений поведения; аварийная защёлка работает.
